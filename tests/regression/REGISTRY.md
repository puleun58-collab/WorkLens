- 영역 ID는 `WS-*`, `LAW-*`, `TOOL-*`, `COMMON-*`. 기존 WF/DOC/XLSX/AGG/UI ID는 영역 접두사 뒤에 유지하고 매핑 칸에 원래 runtime ID/케이스명을 명시한다. 기존 실행 ID·record.ts·report 로직은 변경하지 않는다. Live의 `LAW-01`–`LAW-15`와 기존 `TOOL-*`는 그대로 유지한다. 신규 브라우저 케이스는 `LAW-B01`–`LAW-B06`, `COMMON-B01`이다.
- 실제 발견한 기존 regressionCase는 **211개 고유 ID / 241 viewport 실행**이다 (`bun run test:regression --list`). 최초 목록의 133개와 차이가 있다. 관련된 형식·경계 파라미터는 한 행에 묶고 **기존 모든 211개 ID를 한 번씩 매핑**한다. 묶음의 각 테스트는 모두 실행해야 해당 행을 검증했다고 할 수 있다. 임의 개수 채우기와 테스트 삭제/expectation 완화는 없다.
- 단위/E2E/eval 전체의 개별 assertion/fixture까지 1행씩 펼치는 대신 기능 계약으로 연결한다. Tier는 주 매핑 테스트의 실행 방식이다. Offline 보조 매핑은 별도 표기한다. Offline은 mock/fixture 기반, E2E는 실제 브라우저와 로컬 제품(mock API 포함), Live는 실제 외부 연동이다. mock ID/법률 문구는 실데이터 존재 검증이 아니다.
- Critical: 허위 근거·보호 값 변조·법적 상태 혼동·데이터/보안 경계. Major: 핵심 흐름·내보내기·복구. Minor: 표현/키보드/외관 계약. 등록은 실행 성공을 의미하지 않는다.

## Tier별 실행 명령

모든 `bun run` 이름은 기준 package.json에 존재한다. 전체 Tier 실행과 선택 실행을 구분한다. E2E는 먼저 production build와 설치된 Playwright 브라우저가 필요하며 각 config가 3311/3312에서 `next start`를 직접 띄운다. test:e2e의 기본 config는 worklens/tools/image-batch/aggregation/analysis/analysis-matrix spec만 선택한다. cloudflare/production smoke는 별도 config이며 이 Registry의 기본 Tier2 범위 밖이다.

Tier1 / Offline:

```bash
bun run test
bun run test:eval:retrieval
bun run test:eval:grounding
bun run test:eval:supplement
bun run eval:document-review
# 기본 test에서 제외된 보호 holdout은 명시적으로 실행
bun run eval:document-review:holdout
```

Tier2 / E2E:

```bash
bun run build
bun run test:regression
bun run test:e2e
# 신규 케이스만 선택 (기존 script에 Playwright 인자 전달)
bun run test:regression law.regression.ts
# 실행 artifacts를 정리하는 기존 report (테스트 실행 명령 아님)
bun run test:regression:report
```

report는 cases.jsonl의 ID/viewport별 마지막 결과와 Live law-regression artifact를 합친다. Registry 묶음/Offline eval을 자동 집계하지 않고, 기존 console/network errors 기록을 모두 실패로 간주하지도 않는다. 과거 artifact가 남아 있다면 report를 이번 실행 전체 결과로 오인하지 않는다.

Tier3 / Live:

```bash
bun run test:law-live
bun run test:law-regression
bun run eval:supplement:live
bun run eval:document-review:live
```

각 script의 기존 옵션·필수 환경변수는 [law-live-smoke.ts](../../scripts/law-live-smoke.ts), [law-regression.ts](../../scripts/law-regression.ts), [supplement-eval.ts](../../scripts/supplement-eval.ts), [document-review-live.ts](../../scripts/document-review-live.ts)를 따른다. API key 등의 값은 Registry/로그에 넣지 않는다. LAW-01–15는 기존 15개 실데이터 세트이며, UPSTREAM/네트워크/환경 실패를 코드 실패와 구별한다. 이 변경은 법령 관련 제품 로직/결과를 변경하지 않으므로 의무 Live 재실행 조건에 해당하지 않는다.
